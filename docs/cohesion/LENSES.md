# The cohesion audit's lenses

[COHESION.md](../COHESION.md) §10.4 runs these lenses again. Each lens is the brief of one auditor: what to read, what to ask, and what to probe. The first audit ran all 25 on 2026-11-24, on main at 5c2f35f0. It found 279 distinct defects and confirmed 276.

## The method

1. **Find.** One auditor per lens reads the code and docs its brief names and runs probe programs with the blue that main builds. A finding states its kind and severity, cites file:line or a probe's exact output, proposes the one true way, and names how existing code moves to it (its fixer). The kinds are ambiguity, contradiction, composition gap, duplication, naming, dead or unwired, blank, false claim and gate gap. An absence needs a second probe of a different shape. A deliberate ruling is not a defect, unless it is incoherent with another ruling or with the code.
2. **Merge.** One agent puts findings that share one mechanism and one fix into one cluster.
3. **Check.** A skeptic per finding tries to refute it. It reproduces the evidence, and it looks for a ruling that makes the behaviour deliberate. On the first audit, 471 of 474 checks upheld their finding, so one skeptic per finding is enough.
4. **Critic.** One agent names what no lens read. Its lenses run as a second round.
5. **Plan.** An architect groups the confirmed findings into units, each with its locks, in waves ([COHESION.md](../COHESION.md) §5).

Auditors are read-only. They write probe programs under a scratch directory (`<scratch>` below) and never change a repository.

Severity: critical means ordinary blue gives a wrong answer, or a user must know two systems for one job. High means a visible inconsistency in daily use. Medium means a seam an expert hits. Low means a naming or doc nit.
