## The 5 highest-leverage gaps
1. tenkai? + kenkou?: one rollout vocabulary (plan, step, verify, shift, pause, abort, rollback) over rolling, canary and blue-green as strategy values. The gate verbs `verify` and `kenkou?::gate` keep `blind` distinct from `healthy`.
2. kiban?: declare, plan, drift, import, lock as verbs over Pangea. `apply` stays wave 3 and gated, since writes belong to a reconciler (STDLIB §4.18 spirit).
3. paketto? + bajon?: resolve and lock are the same shape for gen, bidama and registries. Version order and constraint maths become pure and law-testable (laws: compare is a total order; pick(satisfies) is maximal).
4. birudo?: `key`, `stale?`, `restore`, `save` make incremental and cached builds one idiom; `reproduce` turns hermetic claims into a check.
5. kyoukyuu? + konteina?: SBOM, scan, attest and verify as one chain from image to cluster admission, replacing per-tool shell calls (regctl, skopeo, crane) with `copy`, `combine`, `resolve`.

## Stays OUT of blue (and why)
- Compilers, linkers, and container runtimes (runc, kernel namespaces): C-level, contained behind `birudo?::run` and `konteina?::run`.
- Interactive tools: `nix develop`, `kubectl exec`, `docker attach`, interactive rebase: not verbs, they need a TTY.
- Writing unit files, cloud console flows, and IaC providers themselves (generated by iac-forge): declaration owners, not verbs.
- Direct Kubernetes `put/create/delete`: stays GitOps (`gitto::push`, `habu::create`, then a reconciler), per STDLIB §4.18.
- Secret handling: himitsu/cofre own it; `kumo?::whoami` only names the identity.

## Wave order
- W0 (31): rows that exist (kirikae, tehai, kijun, nikkusu, haibi, shinchoku, `paketto?::lock`, `birudo?::check/test/format/doc`): conform names only.
- W1 (152): process-wrapper spaces first, since they need no new runtime: gitto, kurasuta, habu, joujuu, hyouka, kumo? reads, paketto? reads, bajon? (pure), rirezu?/paipurain? reads, kenkou?, haichi?, youryou? reads. Matches STDLIB W6.
- W2 (86): writes with gates and caches: konteina? push/pull, birudo? cache, paipurain? cancel/retry, kiban? plan/drift/lock, tenkai? control verbs.
- W3 (62): irreversible or measured: kiban? apply/destroy, tenkai? shift/analyze/bake, hiyou?, hata?, jikkou?, haifu?, kyoukyuu? deep verbs.
- W4 (15): long horizon: bursts, mirrors, stale flags, forecasting.
Reason: reads before writes, pure before effect, and each later wave reuses the gate verbs (`verify`, `approve`, `lock`, `plan`) proved earlier.

## Risks
- Names are provisional; every `?` space needs the `naming` sweep before landing.
- `tenkai?` and `kiban?` could become a second apply path beside the reconcilers; keep `apply`, `shift`, `promote` behind `capability` and a plan.
- Fleet owners are thin: only gen, forge, fleet, breathe, tameshi, sekiban, cartorio, lacre and the finops forges were read; `doca` is named in the knowledge index but has no repo at the pleme-io root, and `eclusa` appears only as a skill name, so both are `-`.
- `blue_today` for the web of process-wrapper spaces assumes shisutemu/fairu land first (STDLIB W2).
